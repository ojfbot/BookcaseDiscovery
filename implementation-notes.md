Proposed `open-question` for the reader side in `taste-model.md` §9 and left `docs/plan/docs/recommend/taste-tree-ux.md` untouched (it is a frozen plan file; changes go by ruling).
- **2026-11-02 (L-1).** P-2 describes the detect output as `{polygons, scores, version}`. JSON Schema cannot say two arrays have equal length, so Zod and the schema could disagree on a mismatch. Went with `detections: [{polygon, score}]`, plus an `image: {width, height}` echo, in `contracts/helpers/detect-response.schema.json`. P-2 and P-4 read the contract, not the card text.
- **2026-11-02 (L-1).** The card says "polygon in original-image pixels" and leaves EXIF orientation open. iPhone photos are stored landscape with an orientation tag, and detectors differ on whether they apply it. Did not decide: the detect response echoes the decoded `image` size so a caller can check it against `ImageAssetIngested.width/height`. Suggested for K-1/P-2: the working copy is orientation-normalised (pixels rotated, tag cleared) so there is one frame. Conductor to rule.
- **2026-11-02 (L-1).** The card does not fix the polygon's point count. V-1a labels and Vision's perspective crop both need four corners, but P-3's SAM masks are free-form. Fixed `Polygon` at exactly four points; a SAM backend emits the minimum-area rotated quad. Loosening later is cheap, tightening is not.
- **2026-11-02 (L-1).** The card does not say whether `append` checks references. Chose to refuse an event that names an unknown observation, work item or recommendation, or reuses an existing id (`LedgerError`; the refused event leaves the ledger unchanged). Without it a view silently drops the event. L-2's SQLite ledger must match, and `ViewDump` is the equality check.
- **2026-11-02 (L-1).** `StatusChanged` carries `from`/`to` only, with no trigger or cause. L-2 owns the legal-transition table and the rule that `resolved → unresolved` needs a trigger event; a cause enum written here would have decided that for it. L-2 may add an optional field. Likewise the unresolved reason lives on `BandAssigned` (required exactly when the band is `unknown`), not on status.
- **2026-11-02 (L-1).** The card names the event types but not their fields. Fields come from the cards that emit and read them (K-1, P-1, P-4, I-1, I-3, I-4, R-2, R-3). The `Evidence.kind` list, the `ImageRejected` reasons beyond `below-min-resolution` and `no-exif`, `WorkItemOpened.kind` (only `closer-photo`) and the `RecommendationRevised` shape (`previous`, `reasonEventSeqs`, per INV-21) are my reading, not the plan's. Extending an enum later is additive.
- **2026-11-02 (L-1).** Helper-contract Zod validators live in `src/ledger/helper-contracts.ts`, not under `src/perceive/`, so every contract validator has one home. P-1 and P-2's wrappers (`src/perceive/`) import them from there.
- **2026-11-02 (K-2, card session).** The plan (DELIVERY-PLAN, pilot-000 note) calls the set "edited JPEG exports", and the K-2 entry names K-1 and Z-1 as merged. Territory: 5 of 31 are native-size originals; 26 are derivatives (23 portrait frames whose stored pixels are the transpose of their EXIF size with Orientation reset to 1, and 3 landscape frames resampled to 0.929×). Z-1 is not on main. Went with per-file verdicts from the evidence, no suspect files, and a hand privacy check (no coordinates, capture dates, paths or hashes in the doc). The portrait verdict assumes the usual iPhone JPEG layout, which this set cannot check; it is conservative and O-2 settles it.

- **2026-11-02 (K-1).** The card has no settings-map format and the event requires a `setting`. - **2026-11-02 (K-1).** The card says "without exiftool, re-encode with sips and read back". Territory (macOS 27): `sips` keeps GPS and the Orientation tag on a direct re-encode, and cannot read `DateTimeOriginal`, Orientation or GPS at all. Went with: decode through BMP (which `sips` renders with the Orientation applied and which carries no metadata) then re-encode, plus a small native JPEG EXIF reader for reading and read-back. HEIC without exiftool is refused. All of it runs in a test with exiftool forced off.
- **2026-11-02 (K-1).** Normalising Orientation ≠ 1 needs a pixel rotation, which exiftool cannot do, so those working copies are re-encoded by `sips` (JPEG quality `best`, lossy, other metadata dropped) and are not "same pixels" as the original. Orientation 1 stays lossless via exiftool. A real HEIC keeps orientation in the container (`irot`); the test makes one with a one-off Swift script (skipped if `swift` is absent). Not yet seen on a real iPhone HEIC; K-3/O-2 will.
- **2026-11-02 (K-1).** `ImageAssetIngested.capturedAt` must carry an offset, but EXIF `DateTimeOriginal` has none. Used `OffsetTimeOriginal` when present, else labelled the wall-clock time `Z`, which can be wrong by the camera's UTC offset. Ordering within a session is unaffected.
