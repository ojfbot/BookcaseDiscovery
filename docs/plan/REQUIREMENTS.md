## MVP definition of done

On `sf-store-001`, the owner runs:

```
bookcase ingest <export folder> --session sf-store-001
bookcase run sf-store-001
bookcase report sf-store-001
```

The owner then opens a local HTML report that shows all of the following:

1. **Every source photo with every detected spine boxed.** Each box shows its status (`unresolved`, `resolved`, `paused`, `needs-pixels`) and its identity band (`verified`, `probable`, `candidate`, `unknown`).
2. **Per spine:**
   - the OCR variants;
   - the candidate list, including the explicit `unknown`;
   - the evidence;
   - the versions that produced it.
3. **A ranked recommendation list.** Each entry shows its rationale, interest lens, identity band and location. Clicking an entry highlights the spine in the photo.
4. **The unresolved queue, with reasons**, plus "closer photo" work items.
5. **Scorer numbers against the owner's labels**, recorded in `evals/`:
   - spine recall;
   - OCR character accuracy;
   - identity top-1 and top-5;
   - wrong-but-confident rate;
   - adjudication tokens.

The MVP is accepted at **G-MVP**, after the owner has judged the recommendations (O-5).

## Live MVP definition of done (G-LIVE; added by the gap cycle, OC24)

On the owner's phone, pointed at the `sf-store-001` shelves, and on the recorded sweep clips of them:

1. **Labels follow spines, calmly.** Each detected spine shows a box and, once its track is stable, one text label that stays with the spine as the camera pans; a lost spine's label waits up to the HIG grace before vanishing. At most k spines are highlighted under the active lens, and labels change on glass only under INV-24 (OC30, U-1).
2. **Cards fill and revise visibly.** The card list appears from cheap-pass evidence, ranks against the profile, and every revision shows a was/now/why line with an undo (INV-21).
3. **Closer look on demand.** A tracked spine marked `needs-pixels` can request a 48 MP still, which runs the batch pipeline on that spine.
4. **Same ledger.** Every live event lands in the ledger; `replay` is byte-identical; the batch report can be generated from a live session.
5. **Measured, not asserted.** The V-5 live scorer reports, as distributions on the video fixtures: time to first annotation, time to first useful card, window-based live recall next to still recall on the same shelf, ID switches and label change rate, anchor jitter, revision rate, glass-to-glass latency, adjudication calls and spend. The owner's targets (O-7) are the bar.
6. **Nothing retained.** No frame is stored (INV-22; sweep mode keeps only sparse keyframes); spend per session stays under the OC10 ceiling.
7. **Guided sweep.** A held pan with pace cues returns results and a scrub-back replay on the same bookcase (OC31, T-9).
8. **Coverage reported.** Recognition coverage per shelf (identified / total spines, with each `unknown`'s reason) is in the G-LIVE packet (OC32).

The live MVP is accepted at **G-LIVE**. It does not include ARKit world anchors, TestFlight, a product UI or any release of weights, clips or crops.

## Requirements by concern

| Concern | Requirement | Risk | Measure |
|---|---|---|---|
| **Capture** | Ingest a folder of exported files. For each file:<br>• hash it (sha256);<br>• validate it: HEIC/JPEG; pixel dimensions at or above the session minimum (default 12 MP); EXIF `Make`, `Model` and `DateTimeOriginal` present; not a placeholder (zero bytes, `.icloud`, or below the minimum); not an edited derivative (`IMG_E*` name, `.AAE` sidecar or `Software` tag, flagged);<br>• tag its setting (`whole-12`, `whole-48`, `shelf-48`, `overview`);<br>• write a GPS-stripped working copy;<br>• emit `ImageAsset` and `ScanSession` events.<br>Rejected files are listed with reasons and are never processed. | Low | The 1.7 MP chat attachment is rejected with `below-min-resolution` and `no-exif` |
| **Ledger** | One SQLite file holds:<br>• an append-only event log;<br>• materialized current-state views;<br>• a status machine with legal transitions only;<br>• a `replay` command that rebuilds state from the log.<br>Zod schemas cover ledger records only. | Low | Replay of a recorded run yields byte-identical views. An illegal transition is rejected |
| **Perceive** | `detect` helper → spine polygons → shelf ordinal by shelf-band clustering → crops → `ocr-vision` helper at 0/90/270° → text variants with confidences. Every record carries the detector and OCR versions. Perceive holds no bibliographic knowledge. | Low | M1 exit |
| **Catalog** | A local index built from the **ISFDB dump** (OC20; Open Library is post-MVP). Work (ISFDB title) and Edition (ISFDB publication, with ISBN) are kept separate, with source provenance. SQLite FTS5 with a trigram tokenizer serves fragment matching. Live APIs are used only to verify, never to search. | Low | Golden fragment queries (C-3) reach their target top-5 rate. Catalog breadth beyond ISFDB follows C-R (OC32) |
| **Identify** | Retrieval of top-k candidates per spine, always with `unknown`. Joint assignment across the shelf, allowing copies. Evidence bands. Unknown reasons. "Closer photo" work items. One bounded adjudicator call per ambiguous crop, constrained to answer a candidate ID or `none`, cached on (crop hash, candidate-set hash, model). Per-session cap and per-crop retry limit. | Medium (paid calls) | E-4 numbers; spend under the OC10 ceiling |
| **Recommend** | Profile with read, liked, cooler, inferred and unknown entries, each with provenance. No collaborative filtering. Books already read are marked, not recommended. | Low | Owner judgement in O-5 |

## Explicitly out of scope for the MVP (non-goals)

- **Chat surfaces.** No ChatGPT or Claude connectors or MCP tools. E6 is post-MVP.
- **SelfCo/RAG context adapters**, and lenses beyond reading taste.
- **Other ingest paths.** No iOS Shortcut, PHPicker app, osxphotos or PhotoKit for `ingest`, which still reads exported folders (INV-11). *The gap cycle withdrew "no continuous camera" from this list: the live track (S9) captures from the camera, under OC24–OC25.*
- **Cross-photo deduplication.** The capture protocol is one photo per shelf, so a shelf shot twice is a protocol deviation (logged, not merged).
- **Visual memory or embeddings** of confirmed spines.
- **Calibrated probabilities.** The MVP uses evidence bands only.
- **Multi-user tenancy or packaged distribution.** The source is public; G-L covers data licences before anything else ships.
- **Releasing any photo, crop or label.** That waits for G-PUB (curation criteria, redaction of people, signage and GPS, store consent, cover-art copyright, model card).
- **v2, the native iOS *product* app** (Swift plus Python backend helpers), behind G-V2: product UI, ARKit world anchors, TestFlight and App Store, catalog delivery to the phone, ledger sync. The MVP keeps the seams open (ADR §10) and now holds a **spike app** (`apps/live-ios/`, S9) that is not the product (OC19 as amended, OC25).
- **Releasing detector weights** (G-W), active learning, DVC/MLflow, cloud training (OC27, OC28).
- **Building the vault read path for cloud or GPT agents.** That is the owner's separate SelfCo tooling work.
- **An agentic multi-step inference loop**, unless E-4 and G-E4 call for one.
- **Edition-level identification** beyond what an ISBN read gives.
- **Genres other than science fiction.**
- **The Open Library import** (OC20) and **the ChatGPT-export importer** (OC22). Both are post-MVP backlog items.
- **A second detector arm by default** (OC23): SAM runs only if YOLO-OBB misses the pre-registered bar.
